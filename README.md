## 製品概要

**SNSや機種ごとに分断された「一緒に遊ぶための情報」を、1か所に集めてそろえる募集アプリ**

「趣味トモ」は、ゲームや趣味の仲間を探すための募集アプリです。どのSNSに貼った募集リンクからも同じゲームの募集一覧に入れる「募集」、機種をまたいでハマっているものを並べられる「プロフィール」、一度遊んだ相手と次につながる「フレンド」を、1つの場所で扱います。

### 背景(製品開発のきっかけ、課題等）

「今日は少しだけ、気軽に誰かと遊びたい。でも、いつもの友人とは予定が合わない。」

誰かとゲームがしたくても、そのために必要な情報は、SNSや機種ごとに分断されています。

- **募集が散らばっている。** 募集はXやDiscordの各サーバーなどに分かれていて、全部を見られる人はいません。自分の募集も、一部の人にしか届きません。
- **相手の遊び方が分からない。** 同じゲームを遊んでいても、「勝ちにこだわりたいのか、ゆるく楽しみたいのか」「いつ遊べるのか」「ボイスチャットを使うのか」は、募集文やDMで一から確かめるしかありません。ゲームや趣味を並べて見せる場所もなく、SNSのプロフィール欄に書くと浮いてしまいます。
- **一度遊んでも、次につながらない。** 相手がほかに何を遊んでいるか、いま何に熱中しているかが分からず、また誘うきっかけがつかめません。

どれも、情報がばらばらの場所に、自由記述でしか置かれていないことが原因です。そこで、募集とプロフィールを1か所に集め、同じ形にそろえる場所を作りました。

### 製品説明（具体的な製品の説明）

ゲームや趣味を一緒に楽しむ仲間を探すための募集アプリです。アプリ内にDM（個別メッセージ）の機能は設けず、参加希望・承認と、部屋番号・招待URLの共有で、合流まで進めます。

想定する利用の流れは、次のとおりです。

1. **募集を出す。** ゲームや時間、人数、遊び方などを選んで公開すると、リンク入りの招待状ができます。X・Discord・LINEなど、普段使っている場所にそのまま貼れます。
2. **合う募集を選ぶ。** 参加したい人はリンクをブラウザで開くと、その募集を先頭に、同じゲームのほかの募集も並んで見えます。一覧はインストールもログインもせずに見られ、参加希望は Discord・Google・Steam のいずれかでログインして送ります。
3. **承認されたら合流する。** 募集者が参加希望を承認すると、参加が成立し、部屋番号や招待URLが成立した相手にだけ見えます。参加者のゲーム内IDが要るゲームでは、募集者がそのIDを使ってゲーム側で招待します。
4. **次の遊びにつなげる。** 遊び終わったあと、双方が選んだときだけ「フレンド」として残せます。相手が遊んでいるほかのゲームや新しい募集が、また誘うきっかけになります。

### 特長

#### 1. どの募集リンクからも、同じゲームの募集が全部見える

募集は、どこに共有したかにかかわらず、ゲームごとの一覧にまとまります。リンクを開くと元の募集が先頭に、その下に同じゲームのほかの募集が並びます。参加者は一つのリンクから自分に合う募集を探せ、募集者は自分の投稿を見ていない人にも、ほかの人のリンクを通じて見つけてもらえます。

#### 2. ゲームや機種をまたいで、「いまの遊び方」が伝わる

一つのプロフィールに、複数のゲーム（機種・熱量・実力）と、ゲーム以外の趣味や好きなものを並べられます。Steamでログインすると、持っているゲームとプレイ時間を自動で取り込み、ゲームの画像も自動で付きます。届いた参加希望には、Steamのアカウント年数やそのゲームのプレイ時間を「信頼の目安」として出します。

#### 3. 一度遊んだ相手を、別のゲームにも誘いやすい

フレンドになった相手について、遊んでいるゲーム、熱量、遊べる時間が分かります。「このゲームで一度遊んだ人」のほかの一面が見えることで、遊ぶゲームが変わっても関係が続くことを目指します（今は画面のデモで見せています）。

### 解決出来ること

| 仲間探しの困りごと | この製品で変わること |
| --- | --- |
| 募集を探す場所が分かれていて、条件の合う募集を見つけにくい | どの共有リンクからも、同じゲームの募集をまとめて比べられる |
| 同じゲームでも、熱量や時間、VCの希望が合うか分かりにくい | 条件を選ぶ形でそろえるので、参加前に確かめられる |
| 募集文やDMで、条件・合流方法を一から伝える負担がある | 条件の選択、参加希望、承認、合流情報の表示だけで合流まで進む |
| 一度遊んでも、次に何を一緒に遊べるか分からない | 複数のゲームと趣味をまとめたプロフィールから、次に誘うきっかけが得られる |

### 今後の展望

- **合う理由の表示**：参加希望や募集に、「同じくゆるめ」「遊べる時間が近い」といった合う理由を、データベースのデータから出す
- **フレンドの知らせ**：フレンドが新しい募集を出したときに知らせ、その募集から次の参加につなげる
- **条件変更の再確認**：日時や機種などを変えたとき、成立した相手に改めて参加できるかを確かめる
- **アプリ版の通知**：参加希望・承認・開始前の知らせを、スマホの通知で受け取る（配る仕組みは用意済みで、今は止めている）
- **ゲーム以外の募集**：YouTubeの同時視聴のような、ゲーム以外の趣味の募集にも広げる

### 注力したこと（こだわり等）

- **成立した相手にだけ、合流の情報を見せる。** 部屋番号・招待URL・参加者のゲーム内IDは、募集者と成立した相手にしか読めないよう、データベースの行の権限で守っています。募集者が「遊び終える」を押したときや開催を中止したときは、双方から見えなくなります。
- **同時に押されても、約束が崩れない。** 募集の公開・参加希望・承認などの操作は、すべてデータベースの関数で行います。同時に承認しても募集人数を超えて成立せず、通信が切れて送り直しても、同じ操作が二重に行われません。
- **取れなかった値を、0と混同しない。** Steamのプレイ時間は、「取れなかった」「非公開」「0時間」を区別して扱い、取れなかったものを0時間として出しません。
- **日本語でゲームを探せる。** ゲームのデータ（IGDB）は英語の題名が中心ですが、日本語の題名や別名の一部からも探せるようにしました。
- **ゲームの画像を、決め打ちせずに取る。** プロフィールのゲーム画像は、SteamのアプリIDとIGDBの対応から自動で取ります。対応が見つからないゲームは、似た名前の別のゲームの画像を出さず、画像なしにします。

## 動かし方

公開版は https://tkb2616.expo.app で、mainへのpush後、検査が通ると自動で公開されます。

手元で動かすときは、Node.js 24.3以上で次を実行します。

```sh
npm run setup
npm run start:local
```

`http://127.0.0.1:4183/?design=play#/settings` を開くと、Steamでのログインと、そのアカウントのゲーム・プレイ時間を確かめられます。秘密の値（`STEAM_WEB_API_KEY`、`TWITCH_CLIENT_ID`、`TWITCH_CLIENT_SECRET`）は `packages/integrations/.env` に置きます（Git管理外）。

募集・参加・承認をデータベースにつないで使うときは、ルートの `.env.local` に `EXPO_PUBLIC_SUPABASE_URL` と `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` を設定して書き出し直します。設定が無いときは、偽のデータの画面になります。データベース（Supabase）の手元での動かし方は [supabase/README.md](supabase/README.md)、ログイン・外部連携・公開の手順は [documentation/auth-integrations.md](documentation/auth-integrations.md) にあります。

#### API・データ
* Supabase（PostgreSQL・Auth・Edge Functions・Realtime・pg_cron / pg_net）

* Deno（Supabase Edge Functions）
* PGlite（データベースの手元のテスト）、Node.js Test Runner、GitHub Actions、EAS Hosting（公開版）、GitHub Pages（画面のデモ）
